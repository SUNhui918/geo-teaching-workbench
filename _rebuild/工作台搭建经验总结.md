
## 二、核心方法论：本地资源云端化四类方案

这是本项目最有价值的部分。本地课件五花八门，但**云端化的判断路径是固定的**：

| 源文件类型 | 典型例子 | 云端化方案 | 难度 |
|-----------|---------|-----------|------|
| **Flash exe** | 太阳周日视运动、月相演示、公转的意义、地球运动flash | 解包提取 SWF → Ruffle 播放器在线播放（player.html?swf=xxx.swf） | ⭐ |
| **HTML 网页应用** | 太阳视运动轨迹与杆影 | 直接复制进站点，零改造 | ⭐ |
| **普通 exe（Godot 引擎）** | 太阳视运动-冯伟杰 | 浏览器跑不了 → 用其功能重写为 HTML/JS 单文件 | ⭐⭐⭐ |
| **e书工场电子书 exe** | 古生物图谱 | 逆向提取（4字节头+连续zlib流）→ 重建为在线电子书 | ⭐⭐⭐⭐ |
| **PDF 图文卡** | 岩石图谱（24个PDF） | PDF 渲染图片 + OCR 提取文字 → 重建信息页 | ⭐⭐⭐⭐ |
| **在线网址** | 虚拟天文馆、台风网等 | 直接加卡片，纯链接 | ⭐ |

### 关键判断：什么样的 exe 能转网页？

1. 先看文件头：搜 `FWS/CWS/ZWS` → 是 Flash，用 Ruffle 方案
2. 看附加数据：搜 `EBOOKZIP` 签名 → 是 e书工场电子书，走逆向方案
3. 看 PE 节区：`.aspack`/`.upx` 加壳 → 普通 Windows 程序，浏览器基本跑不了，只能重写或放弃

### 技术细节沉淀

- **Flash exe 解包**：直接二进制搜索 FWS/CWS/ZWS 文件头，从 exe 中切出 SWF（注意 CWS=压缩、ZWS=新压缩格式）
- **e书工场逆向**：附加数据 = `[4字节头] + 连续 zlib 流`；页面流与图片流各自按编号但有缺失，用 **JPEG 尺寸自动匹配**建立精确映射；**编码必须 gb18030**（GB2312 遇 GBK 扩展字如"鼩"会解码失败）
- **PDF 转图片站点**：子集化字体的 PDF 无法提取文字（Type0/Identity-H 无 ToUnicode），用 PyMuPDF 200dpi 渲染 PNG → Pillow 转 JPEG q88（81MB→15MB）
- **OCR 补充文字层**：RapidOCR（rapidocr_onnxruntime）轻量中文首选；依赖 opencv-python 44MB，网络慢时用 `curl -C -` 断点续传下载 wheel 本地安装；OCR API 返回 `(result, elapse)`，result 元素是 `[box四角, text, score]`
- **重写 HTML/JS**：Godot exe 功能重写为单文件网页（约900行），天文计算用简化公式（太阳赤纬 -23.44°·cos(2π/365·(day+10))），支持 URL 参数 `?lat=90&day=172&hour=12` 快速定位课堂场景

## 三、工作台页面架构模式（可复制的骨架）

index.html 的核心设计，以后搭同类工作台直接复用：

```
分类数据（JS 数组，8 类）
    └── 卡片（标题/图标/描述/URL/本地标记）
            ├── 在线卡片：点开即访问
            └── 本地卡片：local:true + cloud 字段
                  ├── 本地环境（file://）→ "打开应用"按钮
                  └── 云端环境（http/https）→ "在线播放"按钮
```

- **环境自动检测**：`location.protocol !== 'file:'` 一行代码区分本地/云端
- **分类卡片数据化**：所有站点是 JS 数组，加站点 = 加一行对象，无需改 HTML 结构
- **图谱类资源模板**（古生物图谱/岩石图谱通用）：
  - 深色入口页：左侧可搜索/筛选目录 + 右侧 iframe 内容
  - 上下页导航 + 键盘 ←→ 切换
  - localStorage 记住阅读位置
  - 分类筛选 chips（全部/沉积岩/岩浆岩/变质岩）
  - 数据驱动：toc.json 定义目录结构

## 四、部署与运维经验（最重要的一课）

### 1. 双平台部署是正确决策

| 平台 | 链接 | 特点 |
|------|------|------|
| CloudStudio | app.workbuddy.link | 主用、部署快，但免费沙箱不保证永久 |
| GitHub Pages | sunhui918.github.io | 永久备用、免费、稳定，但国内偶发访问慢 |

**结论：静态站点内容完全可迁移，任何平台都能托管，双保险是标配。**

### 2. GitHub 被墙的绕行方案（可复用到任何 GitHub 操作）

github.com 主域名被封锁，但 **api.github.com 和 *.github.io 可以访问** → 用 Git Database API 绕过：

```
POST /git/blobs      → 上传文件内容（base64）
POST /git/trees      → 组装目录树
POST /git/commits    → 创建提交（保留父提交历史）
PATCH /git/refs/heads/main → 更新分支
POST /repos/xxx/pages → 开启 Pages
```

### 3. 断点续传 + 增量更新的工程保障

- **断点续传**：upload_progress.json 保存 `{文件路径: blob sha}`，重跑跳过已传文件（应对网络中断、后台任务被截断）
- **增量更新**（踩坑后的升级）：只查"文件名是否传过"不够！必须**本地计算 git blob sha**（`sha1("blob " + 长度 + "\0" + 内容)`）与进度文件对比，**内容变了才重传**。否则改过的文件永远传不上去
- **全量验证**：部署后 curl 关键资源 HTTP 200 + 检查页面是否包含新内容关键字

### 4. CloudStudio 的 MIME 坑

**只认标准扩展名**：`.htm` 会被当 octet-stream 触发下载！重建站点一律用 `.html`。`.jpg/.json/.html` 都正常。

### 5. 备份习惯

- 原始文件备份（源素材 + 中间产物）
- 云端部署备份（最新 dist 全量）
- 交付 zip 给用户本地保存 + 夸克网盘留存
- 教训：平台可能收费/停服，**备份 + 可迁移性**是底线

## 五、工程规范（避免返工的检查清单）

1. **源文件与 dist 同步**：每次改完 `cp 源 dist` + `md5sum` 对比确认（本项目踩过 dist 漏同步的坑：加了岩石图谱卡片但 dist 没更新，用户看不到）
2. **JS 语法校验**：`node --check`（或提取 script 后用 node 校验）
3. **部署后验证**：curl 检查关键文件 + 内容关键字检查
4. **中文文件名**：上传/访问正常，但验证时 URL 要编码（`urllib.parse.quote`）
5. **Windows 控制台乱码**：GBK 控制台显示 UTF-8 输出会乱码，属正常现象，看判断结果不看显示
6. **后台任务 2 分钟截断**：大任务拆小 + 断点续传 + 分步执行
7. **Edit 工具需先 Read**：未读文件直接 Edit 会报错

## 六、协作模式复盘（怎么和 AI 配合效率最高）

| 做法 | 效果 |
|------|------|
| 一次给一批修改清单（5个站点一起说） | 批量处理，一次部署 |
| 明确"改完先不部署，全部确认后再部署" | 避免反复上传 |
| 失效网址主动反馈 | 工作台保持干净 |
| 提供参考图（如侧视图考试标准图） | AI 能精确复现教学图示 |
| 有版权顾虑及时提出 | 提前做版权水印/声明（后按需删减） |

## 七、给未来的自己：搭新工作台时的行动清单

1. **盘点素材**：收集所有网址 + 本地课件，分类列出
2. **判断云端化路径**：Flash→Ruffle / HTML→直传 / exe→评估重写 / 电子书→逆向 / PDF→图片+OCR
3. **搭页面骨架**：复用分类数组 + 卡片渲染 + 环境检测模式
4. **本地预览确认** → 同步 dist → 部署 CloudStudio
5. **开启 GitHub Pages 永久备用**（走 API 绕行方案）
6. **双平台验证** → 备份 zip → 交付
7. 每次小改：**增量更新**（脚本已支持）+ 部署后验证
