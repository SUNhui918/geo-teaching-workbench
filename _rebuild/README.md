## 一、先放心：网站不会没

工作台的主站在 **GitHub Pages**：

```
https://sunhui918.github.io/geo-teaching-workbench/
```

网页全部存放在云端仓库里，**不依赖家里这台电脑**。电脑坏了、关机了、断网了，老师和学生照样能打开，一天都不会中断。

`https://10f6b4c78440492ea1341833ee543203.app.workbuddy.link` 是备用沙箱，隔夜会休眠、显示 502，属正常现象，不用管它。

所以最坏的结果只是「暂时改不了内容」，**不是「东西丢了」**。下面讲的是怎么把「改内容的能力」找回来。

## 二、现在一共有三份副本

| 副本 | 位置 | 装了什么 | 整机坏了 |
|---|---|---|---|
| **云端发布版（主）** | GitHub 仓库 `SUNhui918/geo-teaching-workbench` | 全部网页（682 个文件）+ 每一次改动的历史记录 | ✅ 安全 |
| **重建工具箱** | 本文件夹 `_rebuild/`（本身也在 GitHub 里） | 恢复脚本、部署脚本、项目规则、经验总结 | ✅ 安全 |
| **本机完整快照** | `D:\工作台备份_20261107\`（2578 个文件） | 全套工程：素材、脚本、规则、截图 | ❌ 和 C 盘在同一台机器，会一起没 |

关键结论：**GitHub 才是真正的保险箱**。本机备份只是图个方便，不能当唯一的依靠。

## 三、换新电脑后，四步接着干

### 第 1 步：装两样东西
- **Python 3.10 以上**（python.org 或微软商店，安装时勾选 "Add Python to PATH"）
- **WorkBuddy**（日常用对话方式改工作台）

### 第 2 步：把工作台从云端拉回来

把本 `_rebuild` 文件夹拷到新电脑任意位置，在该文件夹里打开命令行，运行：

```
python restore.py
```

脚本会在旁边生成一个 `geo-workbench` 文件夹，里面就是**完整的工作台发布版**，可以直接双击 `index.html` 预览。

- 文件是**从主站 `sunhui918.github.io` 8 线程并发下载**的，不需要令牌、没有次数限制；文件清单从 `api.github.com` 一次取得。这两个域名在国内都能通，**不要去硬开 github.com**（常被墙）。
- 2026-11-08 实测：682 个文件（约 62MB）**约 5 分钟全部拉回，零失败**，首页与本机逐字节一致。脚本还会逐个校验内容指纹，下载错了会自动重试。
- 赶时间可以先跑 `python restore.py --core`：只拉 676 个小文件（约 3 分钟）就得到能用的工作台主体；之后不带 `--core` 再跑一次，自动补齐 6 张图谱大图。
- 中途断了**重跑一次**即可，已下载的文件按内容校验后自动跳过，不会重复下（实测中断后 400 个文件全部正确跳过）。
- 恢复**不需要令牌**；令牌只有第 4 步「推上线」才用得到。
- 如果手边正好有 U 盘或网盘里的 `dist` 快照，直接拷贝比联网恢复更快，脚本可以不用。

> 补充说明：`codeload.github.com` 整包下载在国内实测极慢（30 秒才 1MB），`raw.githubusercontent.com` 常直接不通，所以脚本默认**不**走这两条路；确实需要整包时才加 `--zip`。

### 第 3 步：重新配一把「钥匙」（只为推上线）

旧令牌留在坏掉的电脑里，建议先去 GitHub 把它吊销，再重新生成：

> GitHub 头像 → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → 勾选 `repo` → 生成后立刻复制

两种告诉脚本的方式，任选其一：

- 设环境变量 `GITHUB_TOKEN`（推荐）
- 或在本文件夹新建 `token.txt`，把令牌粘一行进去

⚠️ **`token.txt` 绝不能上传、不能发微信、不能放进任何网页**。这个仓库是公开的，放进去等于把钥匙挂在门上。两个脚本都已内置保护，部署时会自动跳过这个文件。

### 第 4 步：以后改完页面，一句话推上线

```
python deploy.py
```

等 1～2 分钟，刷新主站就能看到新内容。脚本只上传有变化的文件，很快；推送前会核对本地文件数，明显少于云端时会拒绝执行，防止误删线上内容。

## 四、让新电脑上的 WorkBuddy 马上懂规矩

新会话不记得旧电脑上的约定。把下面这句话发给它即可：

> 读一下 `_rebuild/项目规则.md`，以后更新工作台按里面的三条自动执行。

三条规矩是：**① 每次改动写更新日志（首页自动出「新」角标）　② 新工具页面加右下角悬浮工具条　③ 新页面注入署名**。

技术上的历史经验（Flash / 电子书 / 图谱怎么云端化、天地图瓦片级别、中文文件名坑等）在 `工作台搭建经验总结.md`，需要时再翻。

---

## 五、平时只要做一件事

**每次大改之后，打开一下主站看一眼，确认 GitHub 上是最新的。**

只要 GitHub 是最新的，本机备份就不是必需的。可选的习惯：

- 每月把 `dist` 整个文件夹拷一份到 U 盘或网盘（GitHub 已经够了，这是双保险，恢复时也最快）。
- 新做的 HTML 素材（以前放在 `F:\教学工作台素材\`）一定要放进 `dist` 并推上去，否则只存在于本机。
- 修复包、别人发来的课件同理：进了 `dist` 才算真的进工作台。

## 六、两个容易踩的坑

1. **github.com 打不开 ≠ 工作台没了**。国内常墙的是主站域名，`api.github.com`、`sunhui918.github.io` 都能通。工具箱里的脚本只走这两条路，不要因为 github.com 打不开就以为出事了。
2. **公开仓库 = 所有人可见**。任何令牌、密码、密钥都不要写进网页、脚本或截图再上传。本文件夹里的脚本已经把令牌改成从环境变量或 `token.txt` 读取，不含任何明文密钥。
